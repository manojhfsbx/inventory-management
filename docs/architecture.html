System Architecture

Vue SPA calls the FastAPI backend over HTTP; the backend filters in-memory data and returns validated JSON. No database, no auth server, no external services.

Request / Data Flow

Example: a user changes a filter (warehouse, category, status, or time period) on any view.

1

Filter change in UI

User interacts with FilterBar.vue, updating shared reactive state in the useFilters composable.

2

View reacts and calls the API client

A watch() in the active view (e.g. Dashboard.vue, Inventory.vue) triggers a call into client/src/api.js, which builds query params from the current filters.

3

HTTP request over Axios

Request goes to http://localhost:8001/api/... with query params like ?warehouse=...&category=...&status=...&month=....

4

FastAPI routes the request

server/main.py receives the request; optional query parameters are bound directly to the endpoint function signature.

5

In-memory filtering

apply_filters() and filter_by_month() filter the relevant list (inventory, orders, etc.) already held in memory by mock_data.py. A 'all' value on any filter skips that filter.

6

Pydantic validation

The filtered list is coerced into the endpoint's response_model (e.g. InventoryItem, Order) before being serialized to JSON.

7

Response back to the view

JSON lands in the view's raw data ref (e.g. allOrders, inventoryItems). Derived values are recomputed via Vue computed() properties, and the DOM updates.

Notable Design Decisions

No database

All data ships as JSON in server/data/ and loads into module-level Python lists on startup (mock_data.py). Restarting the server resets any in-memory state. Ideal for a workshop demo — zero setup, deterministic data.

Filtering happens server-side

The frontend never filters lists locally — it always sends the current filter state as query params and trusts the API's response. This keeps one source of truth for filter semantics (e.g. quarter → month mapping).

Public repo guardrails

client/.npmrc pins the public npm registry and client/package-lock.json is gitignored, so a locally-configured private registry can never leak into a commit on this public repo.

MCP-driven tooling

Project config wires up the GitHub and Playwright MCP servers (.mcp.json) so Claude Code can manage issues/PRs and drive browser tests against localhost:3000 / :8001 directly.
